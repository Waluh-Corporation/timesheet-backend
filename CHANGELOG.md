# Changelog

All notable user-facing feature updates, improvements, and fixes to the Timesheet platform are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

---

## [Unreleased]

### Added
- **Dynamic Weekend & Holiday Overtime Timesheet Generation**: Added dynamic style adaptation and attendance matrix data rendering for overtime entries logged on weekends (Saturday/Sunday) and public holidays across master generator and vendor template builders (MII, SDD, Adidata, NTT). When overtime activity is present (`hasAct == true`), rows dynamically render clean white background styling, populated start/end times, calculated duration formulas, attendance status, project metadata, and activity remarks.
- **Weekend Inactive Row Remark Standardization**: Standardized master spreadsheet generator (`services/generator.go`) to display `"Weekend"` in the remark column for inactive weekend days without logged activities, matching vendor template behavior and maintaining consistent timesheet presentation.
- **Admin Audit Log Query & Filtering Endpoint**: Added `GET /api/v1/admin/audit-logs` protected by `AuthMiddleware` and `AdminOnly`. Supports pagination with metadata (`page`, `limit`, `total_rows`, `total_pages`) and query filters (`action`, `resource_type`, `actor_username`, `start_date`, and `end_date`), returning structured `response.AuditLogResponse` with raw JSON details (`json.RawMessage`).
- **Dynamic Push Notification Schedule Endpoint**: Added public `GET /api/v1/push/schedule` returning active reminder schedule metadata including hour, minute, active timezone, next run time, and dynamic human-readable description for frontend timesheet reminder displays.
- **Digital Signature & Document Verification QR Code System**: Added a comprehensive hybrid signing architecture for Timesheet and Berita Acara documents combining visual signature images with tamper-evident verification QR codes.
- **Standalone Tabler Document Verification Webpage**: Added a responsive, mobile-first document verification web page powered by the Tabler design system directly accessible at `/verify/doc/:token` for phone camera QR code scans. Features dynamic branding via `APP_NAME`, authenticity status badges, signing audit trail, and responsive cryptographic SHA-256 fingerprint display, while preserving JSON responses for API clients.
- **User Profile Signature Management**: Users can now upload or draw transparent PNG signatures directly in profile settings (`POST /api/v1/user/signature`), stored securely in object storage (S3/MinIO), with retrieval and deletion endpoints.
- **Explicit Timesheet Sign-Off & Period Locking**: Added explicit monthly timesheet sign-off (`POST /api/v1/timesheets/sign`) and revocation (`POST /api/v1/timesheets/revoke`). Signing locks daily activity mutations for the month, calculates an immutable SHA-256 document fingerprint, and embeds the employee's visual signature and verification QR code into generated spreadsheets.
- **Asynchronous Berita Acara Dual-Signature Workflow**: Implemented multi-party signing for Berita Acara. Employees submit their monthly report for witness approval (`POST /api/v1/berita-acara/submit`), dispatching dual alerts (email and web push) to the chosen colleague. The witness reviews pending requests (`GET /api/v1/berita-acara/witness-requests`) and approves (`POST /api/v1/berita-acara/:id/witness-action`) or rejects with revision notes. Fully signed documents embed both employee and witness visual signatures alongside a document verification QR code in OpenXML Word `.docx`.
- **Dedicated Responsive Email Templates**: Created enterprise HTML and plain-text email templates for the witness workflow (`witness_request`, `berita_acara_approved`, and `berita_acara_rejected`) featuring status badges, period metadata, and direct action buttons.
- **Public Document Verification API for Frontend**: Added public JSON verification endpoint (`GET /api/v1/verify/doc/:token`), returning cryptographic audit data (validity badge, signer identities, timestamps, and SHA-256 fingerprint) consumed directly by the frontend verification interface.

### Fixed
- **Timesheet Handler Test End-of-Month Calculation**: Fixed previous-month date computation in `handlers/timesheet_handlers_test.go` to anchor to the first of the month (`firstOfCurrMonth`) prior to subtracting months, preventing date normalization overflows on 31st-day runs (e.g., Oct 31 overflowing Sept 30 to Oct 1) that violated unique activity date constraints.
- **Inadvertent Grey Styling on Weekend/Holiday Overtime Rows**: Fixed an issue in `ResolveDayStyleContext` (`services/builder_common.go`) where weekend and public holiday rows were unconditionally painted with grey background pattern fill (`#AEAAAA` / `#D3D3D3`), overwriting active working day styles even when users logged overtime activity.
- **Attendance Status Fallback on Overtime Entries**: Added safe fallback to `"P"` (or `"H"` for SDD) across template builders (`template_adidata.go`, `template_mii.go`, `template_ntt.go`, `template_sdd.go`) when an activity entry has an empty status string, ensuring complete attendance matrix markings on active overtime days.
- **Verification Page Self-Contained Styling & CSP Whitelist**: Embedded self-contained Tabler-inspired CSS styles and inline SVG icons directly into `verify_document.html` to eliminate external stylesheet dependencies and prevent unstyled page rendering caused by strict Content-Security-Policy (CSP) headers. Also updated CSP in `internal/middleware/security.go` to permit jsdelivr and rsms.me assets, formatted document fingerprint hashes in uppercase, and standardized the document type title to "Berita Acara - Attendance Incident Report".
- **Verification Page English Label Normalization**: Corrected the witness section header in the standalone document verification page (`verify_document.html`) from `"Witness (Berita Acara)"` to strictly English `"Witness"`, maintaining clean bilingual consistency.
- **Berita Acara OpenXML `.docx` Schema Corruption on Signature Embed**: Fixed XML paragraph boundary scanning when inserting digital signatures into signed Berita Acara Word documents. Previously, searching for `<w:p` matched `<w:pPr...>` tags, creating illegal nested `<w:p>` elements that corrupted OpenXML compliance and caused Microsoft Word to trigger a recovery error upon opening. Also replaced empty spacer paragraphs cleanly to maintain the document on a single page.
- **Berita Acara Verification QR Relocation to Word Footer**: Relocated the verification QR code from above the activity table to the document footer on the right margin (`word/footer1.xml`), preventing document overflow and ensuring Berita Acara remains strictly a single-page document.
- **Berita Acara Floating Signatures ("In Front of Text")**: Replaced inline signature pictures with floating OpenXML anchors (`<wp:anchor>` with `behindDoc="0"` and `<wp:wrapNone/>`), allowing signatures to hover naturally above signer name lines without shifting or displacing document paragraphs.
- **Strict Designated Witness Signature Binding**: Ensured the left signature in generated Berita Acara Word documents strictly binds to the designated, approved witness from the submission (`sub.Witness` / `sub.WitnessID`), eliminating previous witness misattribution or duplicate witness signatures.

### Changed
- **Inactive Attendance Status Matrix Marker Blanking**: Standardized attendance matrix rendering across shared builder (`services/builder_common.go`), Adidata template (`services/template_adidata.go`), and master generator (`services/generator.go`) so that inactive attendance status (`"X"`) leaves the status cell blank (`""`) instead of writing `"x"` or `"X"`, conforming to timesheet presentation specifications.
- **Repository Interface Segregation & ACID Transactor Abstraction**: Segregated fat repositories (`UserRepository` into `UserAccountRepository`, `ProfileChangeRepository`, and `PasskeyRepository`; `MasterRepository` into `ApproverRepository`, `CompanyRepository`, `SiteRepository`, `DivisionRepository`, `DepartmentRepository`, `ProjectRepository`, and `HolidayRepository`) with backward-compatible composite interfaces. Introduced the Transactor abstraction (`domain.Transactor` with `repository.GormTransactor`) to guarantee atomic ACID database transactions and row-level locking on multi-table workflows such as `ReviewProfileChange`.
- **Distributed Redis State for WebAuthn Sessions & Cooldowns**: Migrated in-memory WebAuthn ceremony sessions and password reset/IP cooldown trackers from handler memory to Redis. Enables safe multi-pod and horizontal autoscaling in Kubernetes/ECS with atomic single-use session retrieval (`GETDEL`), 5-minute session TTLs, and atomic `SET NX EX` cooldown protection.
- **Verification Page Configurable Timezone Display**: Updated document verification timestamp formatting (`formatDateTime`) in `templates/render.go` to use application timezone configuration (`config.AppLocation()`, respecting `TZ` / `SCHEDULER_TZ` with UTC default) and dynamically format the matching timezone abbreviation (e.g., `UTC`, `WIB`) rather than hardcoding Indonesian Western Time (`WIB`). Maintained backward compatibility via `formatDateWIB` alias.
- **Document Verification & Berita Acara Generator Code Quality Hardening**: Refactored the public document verification controller, template rendering initializers, and OpenXML Word generator pipelines to eliminate redundant string literals, decompose nested execution blocks, and lower cognitive complexity for improved maintainability.
- **Berita Acara Witness Signature Guard on Generation**: Added strict validation to `POST /api/v1/timesheet/generate` preventing timesheet/BA export when the requested period contains Berita Acara entries that have not been approved and signed by the designated witness (`status != signed`). Rejects generation with clear descriptive HTTP 400 errors if not yet submitted, pending witness sign-off, or rejected.
- **Berita Acara Single Monthly Witness Simplification**: Streamlined witness designation so employees designate 1 witness per month (or via monthly witness update), automatically inheriting the locked witness across all daily activities for that month without requiring redundant witness selections and preventing multi-witness conflicts.
- **Berita Acara Submission Monthly Witness Auto-Resolution**: Updated `POST /api/v1/berita-acara/submit` to allow omitting `witness_id` (optional payload), automatically resolving the locked monthly witness from existing Berita Acara activities for that month and synchronizing all monthly Berita Acara activities to the designated witness.
- **Timesheet Delivery Email Template Refinement**: Removed the "Format Berkas" metadata row from timesheet delivery emails (`timesheet.html` and `timesheet.go`) and updated the download button label from "Download Timesheet (.xlsx)" to "Download Berkas" to accurately represent multi-document ZIP bundled deliveries containing both Timesheet spreadsheets and Berita Acara Word documents.
- **Daily Activity Copying Excludes Working Hours & Berita Acara**: Updated previous day activity retrieval (GET /api/v1/activities/previous) to omit Start Time (Time In), End Time (Time Out), and Berita Acara metadata (`is_berita_acara`, `witness_id`, `witness`, and `berita_acara_notes`), ensuring users copy general work descriptions, project, and status while explicitly logging actual attendance hours and recording any incident reports anew.
- **AuthService Extraction & Clean Architecture Separation**: Extracted dedicated domain service `AuthService` in `internal/service/auth_service.go` enforcing the Single Responsibility Principle (SRP). Centralized Argon2id password verification, opportunistic password rehashing, dual-token (access and refresh) issuance, token rotation with family revocation replay detection, and login audit log persistence. Refactored Gin authentication handlers (`handlers/auth_handlers.go`, `handlers/server.go`) into thin controllers decoupled from direct repository access.
- **Tabler-Inspired Transactional Email Redesign**: Revamped all email templates (`layout.html`, `timesheet.html`, `reminder.html`, `setup.html`, `reset.html`, `password_changed.html`, `berita_acara_approved.html`, `berita_acara_rejected.html`, and `witness_request.html`) to follow the Tabler design system. Features modern typography, Tabler brand colors (`#066fd1` primary blue, clean `#f6f8fb` canvas, `#e6e7e9` borders), datagrid key-value metadata cards, Tabler-styled alert callouts, and tailored Dark Mode support (`#0e1726` canvas and `#182433` card surface) across webmail and desktop clients.

### Removed
- **Dead Code Cleanup (Mapper & Domain Entity Layer)**: Removed unused legacy mapper `models/mapper.go` (and `models/mapper_test.go`) and inactive domain entities under `internal/domain/entity/` (`activity.go`, `authenticator.go`, `master.go`, `push.go`, `setup.go`, `user.go`) to eliminate dead abstractions and streamline code maintenance.

## [1.14.0] - 2026-10-18

### Added
- **Berita Acara (Official Word Document Generation)**: Implemented automated Berita Acara document generation (`.docx`) utilizing Go native archive streaming and XML templating based on the corporate `Berita_Acara-Template.docx` format. Captures employee identity, department, group, team lead approver, and dynamically generates rows with Indonesian day names, dates, working hours, and activity explanations for entries marked as Berita Acara.
- **Monthly Single-Witness Locking & Integrity Protection**: Enforced strict business rules ensuring each employee has exactly one consistent witness per month for all Berita Acara records. The initial Berita Acara entry in a calendar month requires and locks the chosen colleague (`witness_id`). Subsequent entries in the same month automatically inherit the locked witness when omitted, while attempts to specify a different witness without an explicit change request are rejected. Selecting oneself, inactive accounts, or non-user roles as a witness is strictly prohibited.
- **Dedicated Witness Discovery & Management APIs**: Added `GET /api/v1/users/witnesses` returning safe public profiles of eligible peer colleagues (`RoleUser`), and `PUT /api/v1/activities/witness` allowing users to atomically reassign their designated monthly witness across all Berita Acara records for a given month in a single operation.
- **Timesheet & Berita Acara Bundled ZIP Delivery**: Upgraded the asynchronous timesheet export pipeline to check for Berita Acara records. When present, both the `.xlsx` monthly timesheet and the generated `.docx` Berita Acara are automatically bundled into a single `.zip` archive (`Timesheet_and_Berita_Acara_<username>_<MM>_<YYYY>.zip`), uploaded to S3 storage, and delivered seamlessly via secure magic download tokens and push/email alerts.
- **Previous Day Activity Description Autofill / Retrieval**: Added `GET /api/v1/activities/previous` endpoint allowing authenticated users to fetch their most recently recorded active daily activity details (including activity description, project, working hours, and status) prior to a given reference date (defaulting to today in WIB). This enables one-click copying and autofilling of yesterday's / previous workday's tasks into today's timesheet entry form.
- **Previous Month Timesheet Access & Entry**: Users can now access, record daily activities, log overtime, and generate timesheet spreadsheets for both the current month and the previous month (maximum 1 month back). Submissions older than the previous month or for future months are strictly validated and rejected for standard users, while administrators maintain unrestricted historical access.
- **Audit Logging & Activity Trail**: Added comprehensive immutable audit logs for administrative actions (account creation, profile modifications, deactivations, personal data anonymization, and profile change reviews) recording actors, target entities, IP addresses, user agents, and metadata.
- **UU PDP Right to be Forgotten (Personal Data Anonymization)**: Added secure data anonymization endpoint (`POST /api/v1/admin/users/:id/anonymize`) allowing administrators to scrub personally identifiable information (PII) including name, email, credentials, and passkeys while retaining historical activity records for regulatory compliance.
- **Redis TLS, ACL & Connection Pool Hardening**: Enhanced Redis integration with TLS encrypted in-flight communication, ACL username authentication, and connection pool controls (pool size, idle connections, timeouts) across the caching layer and background task queue.
- **Server-Side Token Revocation & Active Session Invalidation**: Added Redis-backed JWT blacklisting (`jti`) upon user logout and active account caching to immediately terminate revoked or deactivated sessions.
- **Swagger UI Production Guard & Configuration**: Added `SWAGGER_ENABLED` environment variable controlling interactive OpenAPI documentation mounting. Defaults to enabled in development and automatically disabled in production (`GIN_MODE=release`) to mitigate API schema enumeration and attack surface exposure.
- **Resource Exhaustion & DoS Rate Limiting on Timesheet Downloads and Generation**: Extended IP rate limiting to protect public timesheet download token routes (`/timesheet/downloads/:token`) and resource-intensive generation endpoints against denial-of-service abuse.

### Changed
- **Adidata Overtime (SPL) Consolidation**: Consolidated the Adidata overtime sheet from multiple per-activity sheets (`SPL-1`, `SPL-2`, etc.) into a unified single sheet (`SPL`) matching the latest corporate template (`SPL_Adidata-Template.xlsx`). All monthly overtime entries are now presented in a single tabular list with dynamic row expansion for more than three overtime activities, formula-based total duration calculation (`=SUM(...)`), and hierarchical approver signature sections.
- **Internal Server Error Masking & CWE-209 Hardening**: Hardened HTTP 500 error envelopes in `handlers/response.go` to mask raw technical error details in release mode while recording full diagnostic context to internal structured logs, preventing database schema and stack trace leakage to clients.
- **Subprocess Execution Timeout for PDF Conversion**: Wrapped LibreOffice headless spreadsheet-to-PDF conversion in `services/pdf.go` with a deterministic 30-second context timeout, guarding against hung subprocesses and resource starvation.
- **Timesheet Builders & Auth Architecture Refactoring**: Streamlined workbook generation logic across Adidata, NTT, SDD, and MII templates to reduce cognitive complexity and parameter counts, replaced duplicate string literals with typed constants, and decoupled logout token blacklisting and session revocation handlers for enhanced code maintainability and SonarCloud compliance.
- **Configurable Timezone with UTC Default**: Changed the default application and scheduler timezone to `UTC` across the configuration loader, database connections, daily cron scheduler, background mailer, and timesheet period validation services. Added first-class configuration via environment variable `TZ` (with backward-compatible fallback to `SCHEDULER_TZ`) allowing flexible deployment in any IANA timezone.
- **Responsive Email Template & Cross-Client Compatibility Hardening**: Upgraded all transactional email templates (`layout.html`, `password_changed.html`, `reminder.html`, `reset.html`, `setup.html`, `timesheet.html`) with dual-tier fluid breakpoints (`max-width: 620px` and `max-width: 480px`), centered Microsoft Outlook MSO conditional wrappers for both cards and external footers, full-width responsive action buttons (`.btn-shell` and `.btn-block`), automatic label-value row stacking on narrow smartphone viewports (`.stack-row`), cross-client Outlook font fallbacks, URL break-word wrapping, and dark mode styling across Apple Mail, Gmail, and Outlook.com/Office 365 (`[data-ogsc]` & `[data-ogsb]`).
- **Access Token Expiry Alignment**: Aligned JWT access token lifespan to 15 minutes (`ACCESS_TOKEN_EXPIRY_MINUTES`) while utilizing refresh tokens for long-lived sessions, reducing exposure windows in accordance with OWASP API security guidelines.
- **API Response Sanitization**: Sanitized authentication and passkey responses to return dedicated DTOs (`UserResponse`) instead of raw database entities, ensuring internal database fields are never serialized over the wire.
- **Atomic Quota Counters**: Upgraded timesheet download quota counters to execute atomically via Redis Lua scripts, eliminating race conditions during concurrent download requests.
- **Optimized Daily Reminder Scheduler**: Replaced repetitive user database queries in the reminder scheduler with an efficient single-pass query, improving scheduler throughput and database responsiveness.

### Fixed
- **Berita Acara DOCX Template OpenXML Compatibility**: Resolved XML namespace corruption in the master Word template (`Berita_Acara-Template.docx`) caused by invalid relationship and paragraph namespace attributes (`ns3:id` and `ns2:paraId`). Generated Word documents now open cleanly in Microsoft Word without unreadable content or recovery prompts.
- **Anonymized Account Immutability & Modification Guards**: Prevented modifications to company, department, site, or profile details (`PATCH /api/v1/admin/users/:id`), redundant deactivations (`DELETE /api/v1/admin/users/:id`), and re-anonymization on already anonymized accounts, returning `403 Forbidden`. Enhanced anonymization to transactionally revoke passkeys, push subscriptions, and pending profile change requests, and exposed explicit `is_anonymized` status in user listings.
- **Code Quality & Architecture Robustness**: Enhanced server middleware by decomposing authentication and token revocation workflows into streamlined modules, standardized internal error definitions and query identifiers across user management services and repositories, documented runtime timezone database embedding for containerized environments, and eliminated redundant evaluation expressions.

### Removed
- **Embedded Frontend / SPA Static File Serving**: Removed embedded SPA static file serving, route fallback handlers (`spaHandler`), and static path helpers (`tryFiles`, `isPathWithinRoot`) to maintain a pure, dedicated backend REST API architecture.

## [1.12.0] - 2026-09-26

### Added
- **Asynchronous Timesheet Generation Engine**: High-throughput background generation pipeline powered by Redis (`hibiken/asynq`) with worker concurrency limiting (`EXCEL_MAX_CONCURRENT_JOBS`). Generation requests now return `202 Accepted` with a tracking Job ID, preventing HTTP timeouts and CPU starvation during peak generation windows.
- **Magic Download Tokens & Single-User Quota Enforcement**: Single-user secure download links using Magic Download Tokens with automated quota enforcement (maximum 3 downloads per generation result) and 7-day expiration, eliminating link leakage and unauthorized sharing.
- **Autonomous Cache Evaluation & Re-issue**: Intelligent idempotency check on `POST /api/v1/timesheet/generate` that automatically inspects activity updates (`MAX(updated_at)`), profile modifications, and physical S3 file availability. Re-issues fresh download links in under 5ms without redundant Excel regeneration or S3 file duplication.
- **Fast-Path Redis Counters, Debounce Lock & URL Caching**: Redis-backed atomic quota counters, 10-second distributed debounce locking, and temporary S3 Presigned URL handling to manage network reconnects with 0 MB server file bandwidth.
- **Dedicated Secure Download Endpoint**: Added public `GET /api/v1/timesheet/downloads/:token` endpoint that validates token quota, increments access counts, and issues `302 Found` redirects directly to temporary S3 Presigned URLs.
- **Configurable Download Token Quota**: Added `TIMESHEET_DOWNLOAD_MAX_QUOTA` configuration to `.env` (default 3) allowing administrators to tune maximum downloads permitted per generation link.
- **HTTP HEAD Support on Magic Download Endpoint**: Added `HEAD` method support on `/api/v1/timesheet/downloads/:token` that returns `200 OK` for email security scanners and link preview bots without consuming user download quota.
- **S3-Compatible Object Storage & 7-Day Retention**: Automated storage integration using the official AWS SDK Go v2 supporting AWS S3, MinIO, Cloudflare R2, and Wasabi with automated daily cleanup of expired files and database records.
- **SES-Ready Rate-Limited Transactional Mailer**: Throttled outbound email delivery using token-bucket rate limiting, safeguarding SMTP servers from connection spikes and rate limit penalties.
- **Real-Time Job Notifications & Status APIs**: Web Push notifications and email alerts with direct download buttons when timesheets are ready, alongside `GET /api/v1/timesheet/jobs/:id` and `GET /api/v1/timesheet/jobs` endpoints.

### Changed
- **Asynchronous Generation Contract**: `POST /api/v1/timesheet/generate` now delegates to the background queue returning `202 Accepted` with job metadata (`TimesheetJobResponse`), while retaining backward-compatible synchronous generation if the queue is unconfigured.
- **Clean Architecture & Handler Decoupling**: Refactored HTTP handlers to adhere to Clean Architecture principles by eliminating direct database coupling from `handlers.Server` and all route handlers. Introduced pure domain entities, repository interfaces, and encapsulated business logic within dedicated domain services.
- **Official Timesheet Formats Across All Companies**: Exported monthly timesheets now faithfully match official spreadsheet layouts, colors, and branding for all partner companies (MII, SDD, Adidata, and NTT).
- **Automatic Generation Date in Signatures**: The signature section across timesheets now automatically fills the exact generation date (e.g., `DATE : 26-Sep-2026`).
- **Standardized Attendance Markers & Formulas**: Standardized attendance status markers for SDD timesheets (`H`, `C`, `I`, `S`, `L`) and aligned NTT summary row formulas to use `COUNTIF`.

### Fixed
- **Timesheet Download Counter & Browser Attachment**: Fixed download counter increment issues and added RFC 6266 `Content-Disposition: attachment` headers for immediate browser file downloads.
- **Total Attendance Calculation in Exported Timesheets**: Fixed an issue where the "Total Kehadiran" summary row remained 0 in generated Excel files.
- **Adidata Timesheet Template Alignment**: Aligned cell coordinates, formulas, and headers to match the official Adidata master template.
- **Accurate Working Hours and Total Hours Display**: Formatted daily and total working hours as standard time values (`08:00`, `17:00`) instead of decimal numbers.
- **Accurate App Impacted & Project Selection**: Fixed synchronization issues where project selections and impacted applications were reset upon updates.
